# 병원 예약 관리자

로컬 주소: `http://localhost/hk-global/admin/`

일반 홈페이지에는 관리자 링크를 두지 않습니다. PHP가 실행되는 XAMPP의 Apache/MySQL을 켜고 위 주소를 사용합니다. Live Server에서는 동작하지 않습니다.

## 최초 계정

로그인 화면의 **최초 관리자 계정 만들기**에서 직접 아이디·담당자 이름·비밀번호를 설정합니다. 비밀번호는 해시로만 저장합니다. 설정 화면은 로컬 접속이며 계정이 하나도 없을 때만 열립니다. 생성 후에는 404로 닫힙니다. 테스트 계정이나 공통 기본 비밀번호는 남기지 않습니다.

## 구현 범위

- 예약 목록: 상태별 건수, 이름·이메일·연락처 검색, 20건씩 페이지 이동
- 예약 상세: 환자 입력 원문, 선택 항목의 한국어 설명, 신청 화면 언어, 한국 시간으로 표시한 접수·동의 시각
- 처리: 접수 / 확인 중 / 예약 확정 / 취소, 담당자 메모 누적, 담당자와 변경 시각 기록
- 다른 담당자가 먼저 수정한 예약은 저장을 거절하고 최신 내용 확인 안내
- 상태 변경은 내부 기록이며 환자에게 알림을 발송하지 않음
- 관리자 전용 한국어 화면으로, 공개 사이트 번역 파일과 분리

## 접근 보호

모든 예약 페이지에서 서버 로그인 검사, 계정 활성 상태 검사, CSRF 검사, 출력 이스케이프, 비밀번호 해시 검증을 적용합니다. 애플리케이션의 30분 미사용 및 8시간 경과 자동 로그아웃 제한을 제거했습니다. 브라우저 종료나 서버의 세션 정리 시에는 다시 로그인해야 할 수 있습니다.

동일 계정 5회 / IP 20회 실패 시 최근 실패로부터 15분간 로그인 시도를 제한합니다. 로그인 성공 시 세션 ID를 재발급합니다. 세션 쿠키는 HttpOnly/SameSite=Strict이며 HTTPS에서 Secure입니다. 원격 접속은 HTTPS에서만 허용합니다.

검색엔진 제외 및 브라우저 캐시 저장 금지 헤더를 설정합니다. 관리 페이지 주소는 보조 수단이며 로그인 검사가 실제 접근을 제한합니다.

## DB / 검증

`D:\xampp\php\php.exe scripts/migrate.php`로 `admin_users`, `admin_login_limits`, `reservation_history` 테이블을 준비합니다. 기존 예약을 삭제하지 않습니다.

`python scripts/test_admin.py`는 XAMPP 로컬 환경에서 가상 관리자·예약으로 기능을 검사하고, 성공/실패 모두 finally에서 해당 임시 계정·예약·이력을 정리합니다.

## 카페24 이전 시

실제 DB 연결 설정과 HTTPS를 적용하고, 최초 설정 파일 `setup.php`는 배포에서 제외합니다. 관리자 계정은 준비된 DB를 안전하게 이전하거나 별도 계정 발급 절차로 준비해야 합니다. 슈퍼관리자는 accounts.php에서 일반 관리자 계정을 추가·삭제할 수 있습니다. 비밀번호 재설정 화면은 아직 구현하지 않았습니다.


## 담당자별 계정 관리

- 최초 기존 활성 계정을 슈퍼관리자로 전환합니다. 새 설치에서는 최초 설정 계정이 슈퍼관리자입니다.
- 슈퍼관리자는 상단 **관리자 계정 관리**에서 담당자 이름·아이디·비밀번호를 입력해 일반 관리자를 추가합니다.
- 일반 관리자는 예약 업무만 사용할 수 있습니다. 메뉴를 숨기는 것뿐 아니라 GET/POST 요청 모두 서버에서 권한을 검사합니다.
- 삭제는 계정의 active 값을 0으로 변경하는 방식입니다. 이후 요청과 로그인을 차단하며 기존 예약 이력의 담당자 정보는 보존합니다. 삭제한 아이디는 재사용하지 않습니다.
- 계정 삭제를 펼쳐 확인 체크 후 삭제 확정을 누릅니다. 본인 및 슈퍼관리자는 삭제할 수 없습니다.
- `python scripts/test_admin_accounts.py`로 권한·추가·삭제·삭제 후 세션 차단을 검증합니다. 테스트 계정은 finally에서 정리됩니다.
