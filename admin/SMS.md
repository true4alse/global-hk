# 솔라피 문자 알림 운영

## 로컬 자동 발송 (2026-10-27 설정)

- Windows 작업 스케줄러에 `HK-Global-SMS-Worker`를 등록했습니다. 로그인 중 1분마다 콘솔 창이 없는 `php-win.exe`로 `scripts/send_sms.php`를 직접 실행합니다. Apache를 중지해도 예약 작업은 계속 실행됩니다.
- PHP 경로는 `D:\xampp\php\php-win.exe`이며 현재 프로젝트의 절대 경로로 등록되어 있습니다. 프로젝트를 이동하면 작업의 경로도 수정해야 합니다.
- PC가 켜져 있고 사용자가 로그인되어 있으며 MySQL이 실행 중이어야 합니다. 예약 홈페이지를 이용하려면 Apache도 필요합니다. 절전·로그아웃·PC 종료 중에는 발송하지 않습니다.
- 일시 중지는 작업 스케줄러에서 해당 작업을 찾아 **사용 안 함**, 재개는 **사용**을 선택합니다. 마지막 실행 결과 `0x0`은 작업 정상 종료이며 개별 문자 수신 성공을 뜻하지 않습니다.
- 기존 `unknown` 건은 자동 재발송하지 않습니다. 솔라피 발송 내역에서 확인합니다. 새 예약 테스트는 자동 실행을 기다린 후 휴대폰 수신과 발송 내역을 확인합니다.
- 카페24 자동 실행은 아직 설정하지 않았습니다. 운영 이전 시 호스팅 지원 여부를 확인하고 로컬 예약 작업을 중지합니다.

견본 설정의 기본값은 disabled입니다. 현재 로컬은 사용자가 실제 문자 수신을 확인한 live 설정으로 운영합니다.

## 반복 접수 및 발송 비용 보호

- `scripts/migrate.php`가 `004_abuse.sql`의 보호용 테이블을 생성합니다. 기존 예약은 보존합니다.
- 접수 제한은 최근 10분 기준 IP 5건, 정규화한 연락처/이메일 각각 3건, 동일 내용 1건입니다. 언어와 요청 ID를 바꾸어도 동일 내용은 제한됩니다. DB 잠금으로 동시 요청의 제한 확인을 직렬화합니다. 기존 요청 ID 재시도는 기존 성공 응답을 유지합니다.
- IP는 실제 `REMOTE_ADDR`만 사용하며 클라이언트의 전달 헤더를 신뢰하지 않습니다. 운영 서버가 프록시 뒤에 있으면 신뢰할 프록시 설정을 확인해야 합니다. 같은 네트워크를 쓰는 정상 사용자도 IP 한도를 공유합니다.
- 숨김 `website` 입력값이 채워진 자동입력 요청을 거부합니다. CAPTCHA가 아니며 분산 공격을 완전히 차단하지 않습니다. 외부 공개 전 CAPTCHA/WAF 연동은 별도 준비가 필요합니다.
- 실제 문자 발송 시도는 전체 수신자 합산 최근 10분 20건 / 24시간 100건이 기본 상한입니다. `limit_10_minutes`, `limit_24_hours`로 조정합니다. 상한은 적용 이후 시도부터 계산하며, 재시도 및 결과 불명 요청도 포함합니다. 모의 발송은 제외합니다.
- 상한 초과 건은 `held`로 보류하고 예약 목록에 경고합니다. 예약은 유지하며 보류 건은 다음 날에도 자동 재발송하지 않습니다. 관리자에서 해당 예약을 직접 확인합니다.
- `scripts/test_abuse.php`는 임시 테이블과 가짜 발송 함수로 제한·기간 만료·보류를 검사합니다. 실제 SMS를 보내지 않습니다.

## 준비
1. scripts/migrate.php 실행으로 sms_jobs를 생성합니다.
2. config/sms.example.php를 웹 루트 밖의 비공개 위치에 복사합니다. 키/시크릿/인증된 발신번호를 입력합니다. config/sms.local.php에는 비공개 파일을 require하는 연결만 둡니다. Git에는 포함하지 않습니다.
3. mode: disabled는 대기열도 만들지 않습니다. simulate는 새 예약을 모의 처리하고 네트워크를 사용하지 않습니다. live는 실제 유료 발송입니다. 키 설정만으로 live로 바꾸지 마세요.
4. admin_url은 로컬 테스트에서 비워둡니다. 배포 후 공개 HTTPS 관리자 주소를 설정합니다. 환자 이름·연락처·증상은 문자에 넣지 않습니다. 90바이트를 넘으면 LMS로 발송합니다.
5. Windows 작업 스케줄러 또는 호스팅의 cron에서 PHP CLI scripts/send_sms.php를 1분 간격으로 실행해야 합니다. 예약 API는 외부 서비스를 호출하지 않습니다. Cafe24 상품의 주기 실행/PHP CLI 지원을 배포 전 확인해야 합니다.

## 동작과 실패
- 예약이 저장된 후 활성·수신 설정된 번호만 대기열에 기록합니다. 같은 예약/번호는 중복 등록하지 않습니다.
- 꺼져 있던 기간의 예약을 소급 발송하지 않습니다. 모의 대기열은 live에서 발송하지 않습니다.
- 발송 전 현재 수신 설정을 재확인합니다. 해제/삭제/번호 변경된 수신자 및 24시간이 지난 대기는 취소합니다.
- 단일 DB 잠금으로 작업 동시 실행을 방지합니다. HTTP 429는 5분 간격 최대 3회 시도합니다. 오류/통신 단절/작업 중단으로 접수 여부가 불명확하면 unknown으로 남기며 자동 재발송하지 않습니다.
- accepted는 솔라피 접수 완료이며 단말 수신 성공이 아닙니다. 최종 결과는 솔라피 콘솔에서 확인합니다. 최종 수신 결과 자동 동기화는 별도 후속 작업입니다.
- 계정 관리의 문자 알림 기록에서 최근 100건을 확인합니다. 번호는 마스킹합니다. 비밀키와 업체 응답 원문은 로그에 남기지 않습니다.
- 대기열 DB 오류가 나도 예약은 성공 처리하며 PHP 오류 로그에 HK SMS queue failed가 기록됩니다. 해당 예약은 자동 복구하지 않으므로 이 로그 발생 시 최근 예약을 확인해야 합니다.
- 실발송 테스트는 업체 계정 준비 후 지정된 테스트 번호로만 진행합니다. 기존 담당자 번호로 테스트 문자를 무단 발송하지 않습니다.
